# Challenge Solution (critique a proposal)

## Objective

Desafiar uma solução proposta para reduzir bias e overengineering.  
**Não** significa “implementar o Tech Challenge”; significa **criticar** a proposta.

## Project Context

- Constraints tipadas: `.cursor/context/tech-challenge-requirements.md`
- Stack: Python + FastAPI + NLP + Docker + Airflow + Prometheus/Grafana

## Instructions

Analyze the proposed solution:

1. What can go wrong? (delivery risk vs evaluation weights)
2. Are there simpler alternatives that still meet OBRIGATÓRIOs?
3. Where is overengineering?
4. Were EXEMPLO FIAP items incorrectly locked as mandatory?
5. Were PENDENTE items silently decided?

## Constraints

- Be direct and practical
- Prefer minimal viable challenge completion
- Do not recommend auth/DB/K8s/cloud real unless clearly justified

## Output

Risks, simpler alternatives, overengineering points, recommendations.
